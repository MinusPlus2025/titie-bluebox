# 体贴｜Sensor Evidence Matrix V1

## 0. 目的

这份矩阵不是“把能测的东西全测一遍”，而是回答蓝盒子评委最可能追问的四件事：为什么采、怎么采、进入算法做什么、不能证明什么。

蓝盒子命题允许探索皮肤温度、接触面温度、身体不同部位温差、床上微环境温湿度、出汗、心率、呼吸、翻身、睡姿、睡眠阶段、个人偏好、周期和历史数据，同时明确“不要求全部使用”。因此MVP遵循：**少而有因果用途，不堆传感器。**

## 1. 最重要的概念边界

### 客观温度 ≠ 热感觉 ≠ 温度偏好

- `Temperature`：传感器可测的客观状态。
- `Thermal sensation`：用户主观感觉冷/热的程度。
- `Thermal preference`：用户希望更暖、保持还是更凉。

「体贴」最终服务的是第三项。

2022年6个月个人热舒适纵向研究把用户的thermal preference作为Ground Truth，并把室内温度、近体温度、皮温、心率等与主观偏好配对；研究还使用20/60分钟历史梯度与移动平均。2026年受控实验进一步显示，在相同温度变化条件下，仅改变参与者的温度预期就能改变热舒适评价，而平均皮温和心率没有同步差异。

因此：
> 传感器提供线索，用户反馈提供个人校准；算法不拥有对身体感受的最终解释权。

## 2. 身体区域与采集矩阵

> 六区是MVP“体验与决策区”，不是固定六个传感器。真实产品可使用床垫多节点 + 姿态/接触映射到身体区域。

| 体验区 | 需要理解的问题 | MVP核心信号 | 现实采集候选 | 在算法中的用途 | 边界 |
|---|---|---|---|---|---|
| 头颈 | 被外暴露区域与覆盖身体是否不同 | 近体/环境温度、可选皮温 | 床头近体温度节点；可穿戴/非接触研究方向 | 判断暴露区与整体环境差异 | 不用头颈单点推断全身 |
| 肩背 | 与床垫直接接触处是否积热/潮湿 | 接触面温度、微环境湿度、压力/接触、趋势 | 床垫温度+湿度+压力节点 | 判断接触热积累、识别身体映射 | 翻身后必须重新映射 |
| 腰腹 | 用户是否出现局部“希望暖/凉一点”的模式 | 接触温度、微环境温湿度、可选皮温、趋势 | 床品/床垫节点；未来可穿戴 | 个体化区域偏好 | 禁止从周期直接推出腹部加热 |
| 大腿 | 覆盖与接触区域的局部变化 | 接触温度、局部温湿度、压力 | 床垫节点 | 支持躯干/下肢之间的局部差异 | 不宣称大腿是所有人的主导区域 |
| 膝腿 | 是否出现局部偏好而整床仍稳定 | 温度趋势、接触温度、局部湿度、接触状态 | 床垫节点；可穿戴为补充 | Demo核心：同温下个体/局部不同 | “膝盖凉”是用户观察，不是女性共性 |
| 足部 | 远端热状态是否和其他区域不同 | 接触温度、可选皮温、趋势 | 床端节点；袜式/踝部可穿戴研究方向 | 建立远端区域个体模式 | 单点足温不能直接等于“想暖一点” |

## 3. 全局Context矩阵

| Context | 来源 | 为什么可能有用 | MVP怎么用 | 不允许怎么用 |
|---|---|---|---|---|
| 室温 | 房间传感器 | 区分环境整体变化 vs 局部变化 | 全局背景变量 | 不以24°C之类作为统一舒适阈值 |
| 房间湿度 | 房间传感器 | 影响蒸发与体感背景 | Context | 不单独决定冷热 |
| 睡姿/接触 | 压力阵列/床垫接触节点 | 解决“哪个传感器对应哪个身体部位” | Body-zone mapping | 不用一个固定床区永久代表膝盖 |
| 动作/翻身 | 压力/IMU | 识别姿态改变和数据失效 | 重算mapping/降低confidence | 不把翻身直接解释成热不适 |
| 心率 | 可穿戴 | 个人热舒适研究中的辅助变量之一 | 可选辅助特征 | 不用HR诊断潮热/疾病 |
| 睡眠阶段 | 可靠可穿戴/睡眠设备 | 命题明确提出阶段可能不同 | 可选Context | 没有可靠来源时不伪造“深睡” |
| 时间段 | 系统时钟 | 支持个人夜间模式 | Feature | 不能替代睡眠阶段 |
| 周期信息 | 用户自愿填写/未来健康平台授权 | 体温调节随周期可能变化 | 可选context prior | 禁止固定规则 |
| 潮热/围绝经信息 | 用户自愿 | 对特定用户可能重要 | Use Case / Future model | 不做诊断 |
| 历史反馈 | 用户自己的选择 | 体现“越用越了解人” | Similar Episode Personalization | 不把一次反馈永久固化 |

## 4. 研究依据 → 工程决策

### Evidence A｜睡眠局部热状态
Song et al., *Journal of Thermal Biology* (2020), DOI: `10.1016/j.jtherbio.2019.102480`

研究在睡眠环境中考察局部身体热感觉与整体热舒适关系，识别出背部、面部、大腿等局部区域的重要性，同时指出胸、臂、腿、足也不可忽略。

**工程结论：**
- 身体不能只用一个平均温度表示。
- Body-zone结构有研究依据。
- 论文研究条件为neutral-to-cold环境，不能把其区域权重直接复制成我们的算法权重。

### Evidence B｜个人偏好需要长期个人数据
Tartarini et al., *Indoor Air* (2022), DOI: `10.1111/ina.13160`, PMCID: `PMC9827859`

20名参与者、180天纵向研究；以Right-Here-Right-Now thermal preference为Ground Truth，环境和可穿戴数据为输入。室内温度、近体温度、心率、腕部皮温等是重要变量，研究还计算20/60分钟历史梯度与移动平均。

**工程结论：**
- 使用趋势而不是只看瞬时值。
- 用户自己的`warmer / no change / cooler`适合作为personal calibration标签。
- 我们前台对应：`暖一点 / 刚刚好 / 凉一点`。
- 该研究是建筑热舒适场景，不等同于睡眠床垫效果验证。

### Evidence C｜心理预期改变主观热舒适
Shao et al., *Building and Environment* (2026), DOI: `10.1016/j.buildenv.2026.114437`

相同物理温度变化、不同预期条件下，参与者主观热舒适与降温偏好发生显著变化，而平均皮温与心率未随预期条件同步改变。

**工程结论：**
- 生理数据不能被写成“系统知道你冷”。
- confidence应表达系统不确定性。
- 用户纠正是核心数据而不是失败。

### Evidence D｜女性周期影响体温调节，但不能直接推出偏好
Baker, Siboza & Fuller (2020), DOI: `10.1080/23328940.2020.1735927`, PMID: `33123618`

综述指出排卵后黄体期核心体温通常比卵泡期高约0.3–0.7°C，尤其在睡眠/刚醒时明显。

**工程结论：**
- 周期可以成为可选Context。
- `core temperature change`不能直接推出`wants cooler/warmer`。
- 禁止周期硬规则。

### Evidence E｜Thermal Interoception
Vabba et al., *Neuroscience & Biobehavioral Reviews* (2025), DOI: `10.1016/j.neubiorev.2024.105992`, PMID: `39793684`

综述讨论身体温度觉察如何与生理调节、睡眠、情绪和行为相互作用。

**工程结论：**
- 「体贴」不能把身体体验简化成物理传感器。
- 用户自己的身体觉察应被视作系统的一部分。

## 5. Sensor Node → Body Zone Mapping

真实床垫不应假设：`bed_zone_3 = knee forever`

正确流程：
1. 压力/接触阵列判断人体当前轮廓与姿态。
2. 将温度/湿度节点投影到当前身体区域。
3. 姿态改变时重新映射。
4. 接触丢失时对应Zone数据质量降级。
5. 可穿戴信号属于“人”，床垫节点属于“空间”；融合时保留来源。

建议数据结构：

```ts
interface SensorObservation {
  sensorId: string;
  source: "MATTRESS_TEMP" | "MATTRESS_HUMIDITY" | "PRESSURE" | "WEARABLE";
  value: number;
  timestamp: string;
  quality: "GOOD" | "DEGRADED" | "INVALID";
}

interface BodyZoneMapping {
  zone: BodyZone;
  sensorIds: string[];
  mappingConfidence: number;
  postureVersion: string;
}
```

## 6. 数据质量与失败安全

典型问题：离床、翻身、压力节点映射变化、皮温传感器脱离、湿度瞬时尖峰、数据陈旧、多设备时钟偏差。

产品原则：
- `GOOD`：正常参与模型。
- `DEGRADED`：降低confidence，避免强动作。
- `INVALID`：从特征中移除；关键数据缺失时HOLD/安全停止。
- 干预中信号失效：按安全时长结束，不无限延续。
