# 体贴｜女性用户需求与设计原则 V1

## 1. 我们不是在设计“一个女性模型”

蓝盒子命题以女性睡眠中的冷热变化为出发点，但「体贴」不能把女性变成一组固定生理规则。

更准确的产品问题是：
> 当女性在不同人生阶段、不同夜晚、不同身体状态下感受到细微的冷热变化时，产品怎样不给她一个标准答案，而是逐渐学会她自己的偏好？

## 2. 用户的五个核心需求

### 需求1｜不要因为一处不舒服，把整张床都改变
> “如果只是腿有点凉，我不想整个人都被加热。”

产品响应：身体分区、独立温感偏好、分区控制指令。

### 需求2｜不要假设今天和昨天一样
> “昨天这个温度很好，今天可能就不舒服。”

产品响应：当前趋势优先、Similar Episode而不是永久偏好标签、新反馈可以修改旧模式。

### 需求3｜不要等我醒了再让我自己操作
> “已经醒了再打开手机调温，睡眠已经被打断。”

产品响应：自动但保守、低置信度HOLD、minimal intervention、干预后重新评估。

### 需求4｜不要替我宣布我的身体怎么了
> “设备可以给我线索，但我自己知道我舒不舒服。”

产品响应：“这里可能需要暖一点”、用户可纠正、subjective preference作为校准数据、不用“AI知道你冷”。

### 需求5｜涉及周期、潮热、更年期时给我选择权
产品响应：Context为opt-in、可跳过、不医学化、不做自动诊断、不因为某个阶段固定执行动作。

## 3. 用户界面语言

### 推荐
- 暖一点
- 刚刚好
- 凉一点
- 这里可能需要暖一点
- 暂时不调整，继续观察
- 当前状态和你过去的选择比较接近
- 房间整体变化不大，所以优先照顾这里
- 收到。下次遇到相似状态，会把你的选择算进去
- 如果你愿意，可以告诉我们今晚有什么不同

### 避免
- AI读懂了你的身体
- 检测到你膝盖冷
- 女性身体有多个温度
- 女性更敏感
- 你的身体异常
- 经期模式
- 更年期模式自动开启
- 最佳女性睡眠温度
- 系统比你更懂你的身体

## 4. “体贴”的人机关系

错误：`System senses → System decides truth → User receives`

体贴：`Body signals + environment + user's own feedback → system estimates → user can confirm/correct → model recalibrates`

因此用户不是数据源，也不是被系统研究的对象。**她是个人模型的共同作者。**

## 5. 夜间交互原则

夜里：默认不主动问问题；不弹大量通知；不显示复杂Dashboard；自动控制需要confidence和安全条件；信号不可靠时优先不打扰。

早晨：身体图点选区域；只需“暖一点 / 刚刚好 / 凉一点”即可完成核心反馈；可选补充时间/体验，但不强迫。

## 6. 女性相关Context边界

可以：用户主动选择提供周期阶段、最近容易潮热、围绝经/绝经相关Context；将其作为模型中的低权重先验/相似episode特征；给用户清晰开关与删除选择。

不可以：用性别自动推断身体敏感区；根据年龄自动推断更年期；`period => HEAT abdomen`；`luteal => COOL`；将潮热识别包装成诊断；把群体研究值写成个人事实。

## 7. 产品价值句

推荐：**让冷暖跟着你，不必让你迁就温度。**

功能解释：**哪里需要暖一点，哪里需要凉一点，哪里刚刚好。**

技术表达：**体贴结合身体区域变化、床内微环境与个人反馈，形成可解释的个体温感偏好判断，并把判断转成分区温控指令。**
