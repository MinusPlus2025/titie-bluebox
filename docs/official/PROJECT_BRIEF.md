# PROJECT_BRIEF.md — 体贴

## 1. 项目身份

**产品名：体贴**  
**挑战方：蓝盒子**  
**官方命题：做一款智能调节冷暖的睡眠产品**  
**参赛赛道：软件**  
**产品技术定义：个体化身体温感与分区调节系统**

### 用户价值表达
睡眠里的冷暖很个人。体贴不替用户预设一个“标准温度”，而是结合身体不同区域的变化、床内微环境、睡眠状态与用户自己的反馈，逐渐学会哪里需要暖一点、哪里需要凉一点，什么时候保持刚刚好。

### 核心产品原则
1. 不因为一处觉得冷，就把整个人都变热。
2. 不因为传感器测到一个数值，就替用户定义她的感受。
3. 不为了“智能”而频繁调节；刚刚好时不打扰。
4. 身体状态和个人偏好会变化，模型必须允许更新。
5. 周期、潮热、更年期等信息只在用户愿意提供时作为上下文，不作为自动结论。

## 2. 蓝盒子官方命题约束（开发最高优先级）

### 2.1 命题核心
蓝盒子期待一款能够**主动感知、判断并调节冷暖**的睡眠产品。

软件赛道可重点完成：
- 数据获取与处理
- 人体热舒适/温感判断
- 睡眠状态判断
- 温控策略
- 算法
- 交互系统

硬件赛道可重点完成：
- 传感器
- 温控结构
- 功能材料
- 供电
- 嵌入式控制
- 可穿戴设备、床品或其他睡眠载体

软硬结合是加分项，但官方明确不要求所有链路都必须完整做完；如果只完成其中一部分，要说明上下游，并用数据、测试或对比证明核心环节可行。

### 2.2 官方方向一：先看见具体的人和场景
官方给出的示例包括：
- 经期前后，身体对冷暖的感受可能变化
- 运动后体温、心率上升
- 潮热让人半夜突然醒来并伴随出汗
- 与伴侣同睡，两个人需要不同温度
- 入睡前、深睡、将醒时需求可能不同

这些只是示例，不应硬编码为固定因果规则。

### 2.3 官方方向二：让产品感知她的冷暖
可探索：
- 皮肤温度、接触面温度、身体不同部位温差
- 床上微环境与房间温湿度
- 出汗、心率、呼吸、翻身、睡姿
- 睡眠阶段、个人偏好、周期变化、历史数据
- 传感器、可穿戴、非接触感知、多模态融合

官方明确说“不要求全部使用”。MVP应选择与核心问题最相关、最可行的数据。

### 2.4 官方方向三：把感受变成算法判断
官方特别要求回答：
- 同样室温为什么对不同人意义不同？
- 是否需要整体调温，还是只调整手脚、背部等局部？
- 需求来自睡眠阶段、身体状态、环境还是长期偏好？
- 产品怎样越用越了解人，而不是每晚重新设置？

可使用规则、阈值、算法模型、个人偏好学习等。关键不是术语，而是判断路径可解释，并与真实需求对应。

### 2.5 官方方向四：真正调节冷暖
未来硬件可以是：
- 分区或局部温控
- 空气 / 水循环 / 热电结构
- 相变 / 导热 / 透气等材料
- 床垫 / 枕头 / 被子 / 睡衣等载体
- 入睡前预调节 / 睡眠中自动调节 / 醒前渐变

控制还必须考虑：速度、范围、噪音、能耗、体感和安全。

本软件MVP不假装已有真实硬件，而是通过标准控制指令 + Digital Twin 显示如何与硬件闭环。

### 2.6 官方要求讲清的完整链路
身体与环境数据如何采集  
→ 数据如何处理  
→ 如何形成温感/温控判断  
→ 软件如何生成温控指令  
→ 硬件未来如何执行温度调节

### 2.7 官方评审权重
- 技术路径与专业判断：45%
- 验证与工程实现：30%
- 产品闭环与落地：20%
- 问题定义：5%

因此工程优先级必须是：**模型/工程/验证 > UI包装 > 概念叙事**。

## 3. 我们据此选择的产品切口

### 3.1 核心问题
传统温控往往以“房间温度”或“整床温度”为主要控制对象，但真正的睡眠冷热感受存在三重差异：
1. **人与人不同**：同一个环境温度，不同的人可能希望不同。
2. **身体区域不同**：同一个人同一时刻，肩背、腰腹、膝腿、足部可能并不一致。
3. **同一个人也会变化**：睡眠阶段、身体状态、床内微环境与历史偏好会让需求改变。

因此产品不寻找“女性最佳温度”，也不试图给所有女性建立一个固定模型。

### 3.2 真正预测的对象
不是“几度”，而是每个身体区域此刻的**温度偏好**：
- 暖一点
- 刚刚好
- 凉一点

后台枚举：WARM / HOLD / COOL。

## 4. 女性需求与产品伦理

“体贴”不是把女性当成一种固定生理类型，而是给个体差异留出空间。

必须做到：
- 先听用户自己的感受，再用数据辅助解释。
- 周期、潮热、更年期等信息均为可选输入。
- 不要求用户证明自己的不舒服。
- 不把模糊感受强行医学化。
- 不使用“异常”“女性应该”等语言。
- 不以系统判断覆盖用户反馈。
- 睡眠中尽量不弹窗、不要求操作。
- 早晨反馈尽量轻：点部位 + 暖一点/刚刚好/凉一点。
- 用户可以纠正系统；纠正是个体化学习的正常组成部分。

### 关键用户场景
A. 夜里某个部位需要暖一点，但不希望整张床升温。  
B. 同一个人肩背偏热、膝腿偏凉，希望分区处理。  
C. 同样的房间温度，另一位用户完全不需要调节。  
D. 身体状态改变后，过去“刚刚好”的设定今晚不再合适。  
E. 用户不想半夜醒来拿手机调温，希望系统少打扰地自动处理。

## 5. 身体感知架构

### 5.1 用户可理解的六个体验区
1. 头颈
2. 肩背
3. 腰腹
4. 大腿
5. 膝腿
6. 足部

**体验区 ≠ 传感器节点。** 传感器可以有更多或更少节点；UI按用户能理解的身体区域聚合。

### 5.2 MVP核心数据
每区：
- localSkinTemp
- contactTemp
- localMicroclimateTemp
- localHumidity
- skinTempSlope
- contactTempSlope
- zoneToBodyDelta

全局：
- ambientTemp
- ambientHumidity
- posture / pressure-derived contact state
- movement
- heartRate（可选）
- sleepStage（可选，若由可靠设备提供）
- timeOfNight

用户上下文（可选）：
- personal warm/cool preference
- bedding / sleepwear
- pre-sleep exercise
- cycle context
- hot-flash/perimenopause context
- historical feedback

研究性、非核心MVP信号：
- EDA/皮电（未来潮热事件检测方向）
- 呼吸细节
- 核心体温
- 复杂医疗数据

### 5.3 工程采样建议（非医疗标准）
- 皮温/接触温/微环境温湿度：0.1–1 Hz原始采样；模型使用30–60秒聚合特征
- 压力/姿态：1–10 Hz原始采样，转为姿势与接触事件
- HR：使用可穿戴设备已有数据，按30–60秒窗口使用

核心特征优先用：当前值、移动平均、趋势、相对个人基线、相对身体平均、偏离持续时间、近期干预历史、与历史反馈片段相似度。

## 6. 判断模型

### 6.1 技术原则
MVP不使用LLM判断冷热。

采用**可解释的混合个体化模型**：
1. General Prior：通用热舒适先验
2. Zone State：身体区域状态
3. Personal Calibration：个人/区域偏好校准
4. Control Policy：带滞回和安全约束的控制策略

### 6.2 输出
每个区域输出：
- action: WARM / HOLD / COOL
- userLabel: 暖一点 / 刚刚好 / 凉一点
- intensity: 0–3
- durationMinutes
- confidence
- reasons[]
- reevaluateAfterMinutes

### 6.3 控制约束
必须实现：
- confidence threshold
- hysteresis
- minimum intervention interval
- max intensity
- max duration
- post-intervention re-evaluation

`HOLD` 是重要输出，不是“没有结果”。

## 7. 个体学习

用户反馈是模型的重要标签，而不是附加意见。

早晨身体图：**“昨晚哪里最需要调整？”**  
点区域后只问：
- 暖一点
- 刚刚好
- 凉一点

可选追问：大概什么时候；更像冷、热、潮湿、闷，还是说不清。

保存：userId、zone、时间窗口、sensor features、algorithm decision、confidence、intervention、user preference label。

必须支持：一次或多次反馈后，未来相似场景的个人参数与判断发生合理变化。

## 8. 前端体验

UI语气：安静、体贴、克制、可信。不是医院监护仪，也不是AI炫技Dashboard。

### Screen 1 — 今晚
只显示必要环境与“今晚有什么不同？”（可选）。

### Screen 2 — 身体状态（核心）
人体轮廓为视觉中心。每区显示：暖一点 / 刚刚好 / 凉一点。避免夸张红蓝故障图。

### Screen 3 — 为什么
示例：
“膝腿区域可能需要暖一点”
- 最近15分钟局部温度持续下降
- 与你过去选择“暖一点”时的模式接近
- 房间温度整体稳定
- 因此不需要整床升温

使用“可能”“更接近”，不要说“系统知道你冷”。

### Screen 4 — 夜间时间线
显示信号变化 → 判断 → 动作 → 再评估 → HOLD。

### Screen 5 — 分区执行 Digital Twin
显示区域、方向、强度、持续时间、下一次评估。明确标注 Prototype / Simulated Actuator。

### Screen 6 — 早晨反馈
身体图 + 三点偏好。反馈后显示：
“收到。下次遇到相似状态，会把你的选择算进去。”

### Screen 7 — 验证
比较：整床固定温控 / 固定分区阈值 / 体贴个体模型。

## 10. Digital Twin控制接口
```json
{
  "zone": "knee_leg",
  "direction": "HEAT",
  "level": 2,
  "durationMinutes": 8,
  "reevaluateAfterMinutes": 5,
  "reasonCode": "PERSONAL_COOL_PATTERN",
  "simulation": true
}
```

未来硬件不论采用水循环、热电、加热膜或功能材料，都将抽象指令映射为执行。
